# 2부. 업무 흐름별 사용 설명

[← 목차](./기능-설명서.md)

이 파트는 실무 사용자(본사 관리자, 창고 직원, 거래처 담당자)가 화면을 보고 그대로 따라 할
수 있도록 클릭 순서 위주로 작성했다.

## 2.1 초기 세팅

**목적**: 실적을 기록하고 정산을 계산하려면 카테고리 → 거래처 → 품목 → 차량 단가표 →
전역 설정 순서로 마스터데이터를 먼저 등록해야 한다. 이 순서가 중요한 이유는 품목이
카테고리와 거래처를 참조하고(`apps/api/src/master-data/dto/create-product.dto.ts:6-7`
`categoryId`, `partnerId` 모두 필수), 거래처는 등록 시점에 보관계약을 반드시 함께
입력해야 하기 때문이다.

**사전 준비**: HQ_ADMIN 계정으로 로그인.

**단계별 조작**

1. **카테고리 등록** (설정 → 마스터데이터 → 카테고리 관리, `/master-data/categories`)
   - `+` 버튼 클릭 → 이름 입력 알럿 → 확인. 최상위(1단계)는 자동으로 A, B, C…로 코드가
     부여되고(`categories.service.ts:30-32`), 하위 카테고리(2~3단계)는 `상위코드-01`,
     `상위코드-01-001` 형식으로 자동 채번된다(`categories.service.ts:34-36`).
   - 하위 카테고리를 추가하려면 해당 행의 `+`를 눌러 부모를 지정한다.
   - **주의**: 카테고리는 최대 3단계까지만 만들 수 있다. 이미 3단계인 카테고리 아래에
     하위를 추가하려 하면 `E4105: max category depth is 3` 오류가 뜬다
     (`categories.service.ts:15`).
   - 이름 변경(연필 아이콘), 비활성화(원형-X, 확인 알럿) 가능. 비활성화는 하위 항목까지
     연쇄로 비활성화하지 않으므로, 활성 상태인 하위 카테고리가 트리에서 부모 없이
     남을 수 있다(`categories.service.ts:40-42` 주석 — 알려진 제약).

2. **거래처 등록** (마스터데이터 → 거래처 관리 → `+`, `/master-data/partners/new`)
   - 필수: 업체명, 보관계약(계약유형 + 유형별 필수 필드 + 계약 시작일).
   - 계약유형이 `PALLET_DAILY`면 파렛트 일단가가 필수, `AREA_MONTHLY`/`AREA_YEARLY`면
     면적(평)과 평당 단가가 필수다. 누락 시 저장 버튼을 눌러도 프론트에서 바로
     "파렛트 단가는 필수입니다" / "면적과 단가는 필수입니다" 안내가 뜨고, 우회해서
     API를 직접 호출해도 서버가 `E4103`으로 거부한다(`partners.service.ts:66-78`).
   - 사업자등록번호를 입력하면 10자리 체크섬을 검증한다(알고리즘은 3부 참고). 틀리면
     `E4101`, 이미 등록된 번호면 `E4102`.
   - **중요한 제약**: 보관계약은 **등록 후 수정할 수 없다**. 거래처 수정 화면
     (`partner-form.page.ts`)에는 계약 입력란 자체가 없고, 서버에도 계약을 바꾸는
     엔드포인트가 없다(`partners.service.ts:118-121` 주석 — `areaBillingMode`는 DTO
     검증은 통과시키지만 실제 반영 없이 버려진다). 계약 조건을 잘못 등록했다면
     새 거래처를 다시 만드는 수밖에 없다.

3. **품목 등록** (마스터데이터 → 품목 관리 → `+`)
   - 필수: 품목명, 카테고리, 거래처, 단가(unitPrice), 원가(costPrice).
   - 선택: 건당 운송요율(비워두면 거래처 기본 요율 사용), 파렛트당 최대 적재 수량,
     파렛트 적재 임계 % 오버라이드(비워두면 전역 설정값 사용).

4. **차량 단가표 등록** (마스터데이터 → 운송 단가표, `/master-data/rate-cards`)
   - 화면 하단 "신규 추가" 폼에서 차량유형(필수)과 단가(필수)를 입력, 톤수/컨테이너규격/
     특장사양은 선택 입력.

5. **전역 설정** (같은 화면 상단)
   - **파렛트 적재 기준(%)**: 기본값 70(`rates.service.ts:53-56`, 설정된 적이 없으면
     코드 기본값 70을 반환하며 DB에 실제로 70이 써 있는 것은 아니다).
   - **운송료 계산 방식**: `REPLACE`(차량 단가로 대체, 기본값) 또는 `ADD`(차량 단가에
     건당 요율을 더함). 기본값은 `REPLACE`(`rates.service.ts:66-69`).
   - 각각 별도 저장 버튼이 있다.

## 2.2 엑셀 마스터 이관

**목적**: 거래처·품목을 대량으로 등록할 때 엑셀 업로드로 처리한다.

**사전 준비**: `.xlsx` 파일. `docs/samples/`에 리허설용 샘플 파일이 있다
(`docs/samples/README.md`).

**샘플로 리허설하는 방법**

| 파일 | 구성 | 의도된 오류 행 |
|---|---|---|
| `partners-sample.xlsx` | 10행(8정상/2오류). 열 A~J = code, name, businessRegistrationNo, representativeName, businessType, businessCategory, address, contactName, phone, defaultTransportRate | `KM003`(사업자등록번호 체크섬 오류), `KM007`(업체명 누락) |
| `products-sample.xlsx` | 20행(18정상/2오류). 열 A~H = code, name, categoryName, unitPrice, costPrice, transportRate, palletThreshold, maxUnitsPerPallet | `I-00005`(상품명 누락), `I-00015`(categoryName 누락) |

`transactions-sample.xlsx`(30행, 실적 데이터, 열 A~E = partnerCode/productCode/type/
quantity/transactionDate)는 **마스터데이터 이관 화면에서 쓰는 파일이 아니다**. 이관 화면
컴포넌트(`master-import.page.ts:120`)는 `kind: 'partners' | 'products'`만 지원하며 실적
종류는 아예 선택지에 없다. 이 샘플은 창고 모듈의 "엑셀 일괄 등록" 화면(`/warehouse/import`,
2.3절)에서 쓰는 파일이며, 컬럼 구성이 그 화면의 매핑 필드와 정확히 일치한다
(`docs/samples/README.md:57-75`, `transaction-import.page.ts`).

**단계별 조작** (`/master-data/import`)

1. 대상 선택: 거래처 또는 품목.
2. 대상이 거래처면 화면에 "일괄 적용 보관계약" 입력 블록이 나타난다 — 계약유형과
   유형별 필수 필드, 계약 시작일을 **여기서 한 번만** 입력하면 **이번에 업로드하는
   모든 행에 동일하게 적용된다**(개별 거래처마다 다른 계약 조건을 줄 수 없음). 대상이
   품목이면 "기본 거래처"를 하나 선택해야 하며, 역시 이번 배치의 모든 품목이 그
   거래처에 일괄 귀속된다(품목 엑셀에는 거래처 컬럼이 없음,
   `docs/samples/README.md:53-55`).
   - **주의**: 계약 조건이나 소속 거래처가 행마다 달라야 한다면 엑셀 이관을 쓰지 말고
     2.1절의 개별 등록 화면을 이용해야 한다. 보관계약은 등록 후 수정도 안 되므로
     한 번 잘못 배치 적용하면 되돌릴 방법이 없다.
3. 파일 선택 후 필드→열(A~Z) 매핑을 지정한다.
4. "파일 분석" 클릭 → 서버가 파싱해 정상/오류 행을 나눠 보여준다. 오류 행에는 사유가
   함께 표시된다(예: "업체명 누락", "사업자등록번호 체크섬 오류", "상품명 누락",
   "categoryName 누락", "단가 숫자 아님"/"원가 숫자 아님").
5. 오류 행은 그대로 두고 "N건 반영" 클릭 → 정상 행만 커밋된다(부분 성공). 실패한 개별
   행은 결과에 사유와 함께 표시된다.
6. 품목 이관 시 엑셀에 없던 카테고리명이 있으면 자동으로 1단계 카테고리가 새로 생성된다
   (`excel-import.service.ts:124-129`).

## 2.3 일상 입출고 기록

**목적**: 창고에서 실제로 벌어진 입고/출고를 시스템에 남긴다. 이 기록이 운송료·보관료
계산의 원천 데이터가 된다.

### 경로 A. PWA 직접 입력 (`/warehouse/entry`)

1. 거래처 선택(필수) → 품목 선택(필수, 거래처를 고른 뒤 검색 가능).
2. 구분(입고/출고 세그먼트, 기본값 입고) 선택.
3. 수량(필수, 1 이상 정수) 입력.
4. 일자(필수, 기본값 오늘 — 브라우저 로컬 기준으로 계산됨, UTC 변환 아님).
5. 차량(선택) — 운송료를 차량 단가로 계산하고 싶을 때만 선택.
6. "저장" 클릭.
   - 필수값 누락 시 "필수 항목을 입력하세요.", 수량이 정수/1 미만이면 "수량은 1 이상의
     정수로 입력하세요."라는 프론트 검증 메시지가 뜬다.
   - 해당 일자가 이미 마감된 달에 속하면 서버가 `E2002`를 반환하고 화면에는 "해당 월은
     정산 마감되어 입력 불가"가 표시된다.
   - 선택한 품목이 선택한 거래처 소속이 아니면 `E4106: product does not belong to
     partner` 오류가 난다(`transactions.service.ts:19-24`) — 보통 거래처를 잘못
     선택했을 때 발생한다.

### 경로 B. 엑셀 업로드 (`/warehouse/import`)

1. `.xlsx` 파일 선택.
2. 필드→열 매핑: `partnerCode`, `productCode`, `type`(입고/출고), `quantity`,
   `transactionDate` 5개를 A~Z 열에 매핑한다.
3. "파일 분석" 클릭 → 서버가 행별로 검증한다(`transaction-import.service.ts:36-84`).

   | 오류 상황 | 표시 메시지 |
   |---|---|
   | 거래처 코드 미등록 | `거래처 코드 없음: {code}` |
   | 품목 코드 미등록 | `품목 코드 없음: {code}` |
   | 품목이 해당 거래처 소속 아님 | `품목이 해당 거래처 소속 아님` |
   | 구분 값이 입고/출고/INBOUND/OUTBOUND가 아님 | `구분 값 오류: {value} (입고/출고)` |
   | 수량이 1 이상 정수가 아님 | `수량 오류` |
   | 일자 파싱 실패 | `일자 파싱 실패` |

4. "N건 반영" 클릭 → 정상 행만 커밋(부분 성공). 이미 마감된 달의 일자가 섞여 있으면
   해당 행만 `E2002` 사유로 실패 처리된다(행 단위 try/catch,
   `transaction-import.service.ts:86-98`).

## 2.4 월 정산 마감

**목적**: 한 달치 실적을 확정해 거래처별 청구 금액을 고정한다.

**단계별 조작** (`/settlement-fees/close`)

1. 월 선택(연-월 피커).
2. "미리보기" 클릭 → 거래처별 운송료/보관료 합계와 함께, 계산 도중 발생한 오류가
   배지와 목록으로 표시된다(오류 코드 + 메시지 + 관련 거래 ID).

   | 오류 | 발생 조건 | 해소 방법 |
   |---|---|---|
   | `E4108` | 출고 건에 적용할 운송 단가가 하나도 없음(차량 단가도, 품목 단가도, 거래처 기본 단가도 없음) | 해당 품목/거래처에 요율을 등록하거나 차량을 지정 |
   | `E4111` | 당월 거래는 있는데 그 거래처의 활성 보관계약이 없음 | 거래처에 보관계약이 등록돼 있는지, 비활성 처리되지 않았는지 확인 |
   | `E4112` | 당월 거래가 있는 거래처가 비활성 상태임 | 거래처를 다시 활성화하거나, 그 거래처 실적이 잘못 등록된 것인지 확인 |

3. 오류가 하나라도 있으면 "마감 실행" 버튼이 비활성화된다(`monthly-close.page.ts`,
   `totalErrors() > 0`이면 비활성). 위 표의 방법으로 원인을 해소한 뒤 다시
   "미리보기"를 눌러 오류가 0건이 되는지 확인한다.
4. 오류 0건 확인 후 "마감 실행" 클릭 → 서버가 해당 월의 `SettlementRecord`를 전부
   재계산해 저장하고, `SettlementPeriod`를 `LOCKED` 상태로 잠근다
   (`settlement-fees.service.ts:193-226`). 마감 실행 응답에 오류가 남아 있으면(마감
   버튼을 누르는 사이 새 실적이 들어온 경우) 화면이 자동으로 미리보기를 다시
   실행해 최신 오류 목록을 보여준다(`monthly-close.page.ts:129-135`).
5. 마감 완료 후 거래처별 "정산서 바로가기" 링크가 표시된다.

**마감 후 해당 월 실적 입력이 막히는 이유(E2002)**: 마감 시 저장되는
`SettlementPeriod.status`가 `LOCKED`가 되면, 이후 그 기간(`periodStart` 이상,
`periodEnd` 미만)에 속하는 일자로 새 실적을 등록하려 할 때마다
`transactions.service.ts:34-47`의 조회가 이 잠금 레코드를 찾아내 `E2002: settlement
period is locked`를 던진다. PWA 입력과 엑셀 업로드 모두 같은 검증을 거친다.

**해제 방법**: 이 창고 모듈에는 전용 잠금 해제 화면이 없다. 실제로는 레거시 정산 모듈의
`POST /settlement/:id/unlock`(HQ_ADMIN 전용,
`apps/api/src/settlement/settlement.controller.ts:162-171`)이 같은 `SettlementPeriod`
테이블의 `status`를 `OPEN`으로 되돌리는 방식으로 동작한다. 이 엔드포인트는 원래
주문/배송 정산 잠금을 위해 만들어진 것을 창고 정산 잠금(sentinel `branchId = 'WAREHOUSE'`,
`apps/api/src/warehouse/constants.ts:4`)에도 재사용하는 구조로 보이며, 창고 전용으로
설계된 화면/버튼이 별도로 존재하는지는 `확인 필요`다. HQ_ADMIN 권한이 있는 담당자에게
해제를 요청해야 한다.

## 2.5 계산 근거 확인(breakdown)

**목적**: 특정 실적 1건의 금액이 왜 그렇게 나왔는지 확인한다.

**접근 경로**: 정산서 화면에서 운송료 항목을 클릭하거나, 대시보드/마감 화면에서 이동.
HQ_ADMIN은 `/settlement-fees/breakdown/:id`, 거래처 담당자는 `/portal/breakdown/:id`
(둘 다 같은 화면 컴포넌트).

- **운송료 근거**: 요율 출처(차량 단가/품목 단가/거래처 기본 단가 중 어느 것이
  적용됐는지), 계산 방식(REPLACE/ADD), 적용 요율, 계산식 문자열을 보여준다. ADD
  모드일 때는 차량 단가와 건당 요율을 항목별로 따로 보여준다.
- **보관료 근거(파렛트 계약)**: 파렛트 일단가, 총 파렛트일수, 계산식, 품목별 상세
  (파렛트일수와 적용 기준 %)를 보여준다. 다음 두 경고가 함께 표시된다.
  - **파렛트당 최대 적재수량 미설정 품목**: 계산에서 제외됐다는 경고.
  - **음수 재고 품목**: 출고 기록이 입고 기록보다 많아 재고가 음수가 된 날이 있으면
    그 품목은 그 날 과금하지 않고 "입고 누락 의심" 경고로 표시된다
    (`storage-fee.ts:75-79`).
  - 파렛트 수가 0이 되는 "서비스 처리"(잔여 수량이 임계 미만이라 파렛트로 셈하지
    않음)는 경고가 아니라 정상적인 계산 결과다.
- **보관료 근거(면적 계약)**: 계약유형, 면적, 평당 단가, 청구 방식(월정액/일할),
  일할이면 대상일수와 월 전체 일수, 계산식을 보여준다.

## 2.6 거래처 포털 사용

**목적**: 거래처 담당자(PARTNER_COORDINATOR)가 자기 거래처의 물량과 청구 근거를 직접
확인한다.

**볼 수 있는 것**

- 포털 홈: 이번 달 운송 건수와 총 금액 요약(`portal-home.page.ts`). 로그인 계정에
  연결된 `partnerId`가 없으면 "거래처 정보가 없습니다"만 표시되고 API 호출 자체를
  하지 않는다. 아직 마감 전이라 데이터가 없는 경우와 "정산 결과 없음"을 화면에서
  구분하지 않는다(둘 다 0건으로 보임 — 알려진 제약).
- 내 물량(`/portal/my-transactions`): 자기 거래처의 입출고 실적 목록, 기간 필터,
  출고명세서 다운로드.
- 내 정산서(`/portal/my-statement`): 월 선택 후 운송료 내역(건별 계산근거 링크 포함),
  보관료 합계, 총계, 엑셀 다운로드.

**볼 수 없는 것**: 마스터데이터, 창고 메뉴, 정산 대시보드/마감 화면은 라우트 가드가
아예 진입을 막는다. 거래처 선택 UI 자체가 없다 — 요청에 담긴 `partnerId`는 항상
로그인 사용자의 JWT 값이 쓰이고, 다른 거래처 데이터를 요청해도 서버가
`E4110: access denied to other partner data`로 거부한다
(`settlement-fees.controller.ts:36-44`, `getBreakdown`/`getStatement`의 스코프 검사).
