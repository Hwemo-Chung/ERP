이 파트는 2026-07-26 로컬 환경(Postgres 15 / API / 웹 모두 기동 중)에서 실제로
재검증한 결과를 담았다. 예전 버전은 P0-1/P0-2/P0-3(3부 3.0·3.6·3.7절)이 "아직 계획

### EXCLUDE 제약 실제 거부 확인 (애플리케이션 우회, raw SQL 직접 실증)

`E4113` 애플리케이션 가드를 거치지 않고 `psql`로 직접 기간이 겹치는 이력 행을
INSERT해 DB 제약 자체를 시험했다:

```
INSERT INTO partner_transport_rate_histories (...)
VALUES (..., '해당 파트너', 9999, '2026-07-05', '2026-07-20');
→ ERROR: conflicting key value violates exclusion constraint
  "partner_transport_rate_histories_no_overlap"
  DETAIL: Key (partner_id, daterange(...))=(..., [2026-07-05,2026-07-20)) conflicts
  with existing key (..., [2026-07-01,2026-07-16))
```

애플리케이션 계층(`E4113`)과 DB 계층(EXCLUDE) 이중 방어가 둘 다 실제로 동작함을
확인했다.

- `E2E_LIVE=1` 전용 e2e 스위트(월 마감 → 잠금 → 정산서 다운로드 전 과정)는 이번

  실제 동시성 부하 테스트는 별도로 필요하다.

## 6.2 알려진 제약 (여전히 유효한 항목만)

- **웹 유닛테스트 171건 선재 실패**: 6.1절에서 오늘 재실행해 재확인했다.
  `ENVIRONMENT_CONFIG` 의존성 주입 문제이며 이 매뉴얼이 다루는 기능들과 무관하다.
  새 기능 관련 회귀인지 판단할 때 이 171건과 혼동하지 않아야 한다.
- **보관료 계산 경로의 예외 처리 비대칭**(3.5절 상세): 운송료 계산은 `computeMonth`
  안에서 `try/catch`로 감싸져(`settlement-fees.service.ts:90-120`) `E4108`이 오류
  목록에 정상 수집되지만, 보관료 계산(`calcStorageFeePalletDaily`/
  `calcStorageFeeArea` 호출, `:143`, `:158`)은 감싸져 있지 않다. 품목의
  `maxUnitsPerPallet`이 0 이하로 잘못 등록되면 미리보기가 오류 배지 없이 처리되지
  않은 예외(500 추정)로 실패할 수 있다. 이 경우 해당 월 거래에 걸린 품목들의
  파렛트당 최대적재수 설정을 먼저 점검해야 한다.
- **보관계약 수정 엔드포인트 부재**: 보관계약(`StorageContract`)은 거래처 생성
  시점에만 만들 수 있고, 이후 계약유형·요율·면적 등을 바꾸는 PATCH/PUT 엔드포인트가
  없다(`partners.controller.ts` 전체를 확인 — `storageContract` 관련 쓰기 메서드는
  `create` 안에만 있음). `UpdatePartnerDto.areaBillingMode`는 DTO 검증은 통과하지만
  `PartnersService.update`가 이를 즉시 구조분해로 버린다(`partners.service.ts:136`
  주석 — "계약 수정 플로우가 아직 없어 저장하지 않고 버린다"). 계약 조건을 잘못
  등록했다면 거래처를 새로 만드는 수밖에 없다(2.1절 동일 내용).
- **거래처/품목 상세 조회 API 부재**: `GET /master-data/partners/:id`,
  `GET /master-data/products/:id`가 없어 프론트가 목록 화면에서 넘긴 라우터 상태에만
  의존한다(4.1절). URL 직접 진입이나 새로고침 시 데이터가 사라지는 것은 버그가
  아니라 이 구조적 한계 때문이다.
- **정산 대시보드 상위 5 순위 근사치**: 실제 물량이 아니라 운송료+보관료 합산
  금액의 근사치다(4.3절, `fee-dashboard.page.ts:76-78`). 거래처 목록 조회도
  `pageSize:100` 상한이 있어 거래처가 100곳을 넘으면 드롭다운에서 일부가 누락될 수
  있다.
- **포털 홈의 "마감 전"과 "실적 없음" 미구분**: `getStatement`는 정산 자체가 없으면
  그냥 0건을 반환하므로, 이번 달이 아직 마감되지 않은 경우와 실제로 거래가 없는
  경우가 포털 홈 화면상 똑같이 보인다(4.4절).
- **DEMO-A/DEMO-B에 연결된 포털 계정 없음**: `scripts/seed-demo-settlement.mjs`가
  만드는 정산 시연 데이터는 `admin` 계정으로만 조회할 수 있다. `partner-a`/
  `partner-b` 계정은 `prisma/seed.ts`가 만드는 별개의 레거시 거래처에 연결돼 있어,
  이 계정으로 포털에 로그인해도 DEMO-A/DEMO-B 데이터는 보이지 않는다(5.7.5절).
