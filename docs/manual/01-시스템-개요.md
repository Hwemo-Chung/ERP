# 1부. 시스템 개요

[← 목차](./기능-설명서.md)

## 1.1 무엇을 하는 시스템인가

이 시스템은 물류센터의 입출고 실적을 기록하고, 그 실적을 근거로 거래처별 운송료·보관료를
자동 계산하는 창고 정산 ERP다. 창고 직원 또는 거래처가 품목의 입고/출고를 PWA 화면이나
엑셀 업로드로 등록하면, 본사 관리자는 월 단위로 그 달의 운송료·보관료를 미리 계산해보고
(미리보기), 오류가 없을 때 월을 마감한다. 마감된 월은 거래처별 정산서(운송료 내역, 보관료
내역, 합계)로 출력할 수 있고, 거래처 담당자는 포털에서 자기 거래처의 실적과 정산서만
조회·다운로드할 수 있다. 마감이 끝난 달은 실적 입력이 잠기며(`E2002`), 잠금 해제는
HQ_ADMIN 권한으로만 가능하다.

## 1.2 역할별 권한

`prisma/schema.prisma:33-39`의 `Role` enum에는 실제로 5개 값(`HQ_ADMIN`, `BRANCH_MANAGER`,
`PARTNER_COORDINATOR`, `INSTALLER`, `WAREHOUSE_STAFF`)이 존재한다. 이 중 `BRANCH_MANAGER`는
레거시 주문/배송 정산 모듈(`apps/api/src/settlement/`, `apps/api/src/orders/` 등)에서만
쓰이며, 본 문서가 다루는 마스터데이터·창고·정산요금·거래처포털 4개 모듈에는 전혀 등장하지
않는다. `INSTALLER` 역시 설치완료 처리(`apps/api/src/completion/`) 등 다른 기능 전용
역할이며, 아래 4개 모듈의 컨트롤러 어디에도 `@Roles(Role.INSTALLER)`가 없다.

| 역할 | 마스터데이터 | 창고 실적 | 정산 요금 | 거래처 포털 |
|---|---|---|---|---|
| **HQ_ADMIN** | 전체 CRUD(카테고리/거래처/품목/차량단가표), 엑셀 이관, 전역설정(파렛트임계·차량요율모드) 변경 | 실적 등록/조회/엑셀 일괄등록, 출고명세서 다운로드 | 미리보기/마감 실행, 모든 거래처의 계산근거·정산서 조회 | 접근 불가(라우트 가드가 HQ_ADMIN 전용으로 막음) |
| **WAREHOUSE_STAFF** | 거래처/품목/차량단가표 **조회만** 가능(생성·수정 불가). 응답에서 **단가·원가·요율 필드가 제거됨** | 실적 등록/조회/엑셀 일괄등록 가능 (HQ_ADMIN과 동일 범위) | 접근 불가 | 접근 불가 |
| **PARTNER_COORDINATOR** | 접근 불가 | 자기 거래처 실적만 조회, 출고명세서 다운로드(자기 거래처로 강제 스코프) | 자기 거래처의 계산근거·정산서만 조회/다운로드 | 포털 전용 화면 이용 |
| **INSTALLER** | 해당 없음(이 4개 모듈에 권한 정의 자체가 없음 — 주문/설치완료 등 다른 업무 전담) | 해당 없음 | 해당 없음 | 해당 없음 |

**WAREHOUSE_STAFF 단가 노출 제거 근거**: `apps/api/src/common/staff-price-visibility.util.ts`의
`isStaffOnly(roles)`는 `roles.includes(WAREHOUSE_STAFF) && !roles.includes(HQ_ADMIN)`일 때만
참이 된다(두 역할을 동시에 가진 사용자는 전체 데이터를 본다). 이 함수는 세 곳에서 호출되어
필드를 완전히 제거한다(값을 가리는 것이 아니라 응답 객체에서 키 자체를 삭제).

| 호출 위치 | 제거되는 필드 |
|---|---|
| `apps/api/src/master-data/partners.service.ts:123-125` | `defaultTransportRate`, `storageContracts`(보관계약 전체) |
| `apps/api/src/master-data/products.service.ts:72-74` | `unitPrice`, `costPrice`, `transportRate` |
| `apps/api/src/master-data/rates.service.ts:48-49` | 차량 단가표의 `rate` |
| `apps/api/src/warehouse/transactions.service.ts:172-174` | 실적 목록에 포함된 `vehicleRate.rate`(`stripRate()` 헬퍼, `:179-182`) |

거래처/품목/차량 단가표 3종 모두 **쓰기(POST/PATCH)는 클래스 레벨 `@Roles(Role.HQ_ADMIN)`만
허용**하고, **읽기(GET)만** 메서드 레벨에서 `@Roles(Role.HQ_ADMIN, Role.WAREHOUSE_STAFF)`로
재정의한다(`partners.controller.ts:28-29`, `products.controller.ts:28-29`,
`rates.controller.ts:29-30` — 각 주석에 "warehouse staff need the ... dropdown for
transaction entry (read-only)"라고 명시). 요율 이력 조회 3종
(`GET .../:id/rate-history`)은 이 재정의 대상이 아니라서 **HQ_ADMIN 전용**으로 남는다
(5.3절 참고).

## 1.3 화면 지도

라우트 가드는 `apps/web/src/app/app.routes.ts`, 진입 메뉴는
`apps/web/src/app/features/settings/pages/settings-menu/settings-menu.page.ts`에 있다.
가드를 통과하지 못하면 `/tabs/settings`로 되돌아간다(별도 403 화면 없음,
`apps/web/src/app/core/guards/role.guard.ts`).

| 라우트 | 화면명 | 접근 역할(roleGuard) | 진입 경로(설정 메뉴) |
|---|---|---|---|
| `/master-data` (`''`) | 마스터데이터 메뉴 | HQ_ADMIN | 설정 → "마스터데이터" 카드 |
| `/master-data/partners`, `/partners/new`, `/partners/:id` | 거래처 목록/등록/수정 | HQ_ADMIN | 마스터데이터 메뉴 |
| `/master-data/products`, `/products/new`, `/products/:id` | 품목 목록/등록/수정 | HQ_ADMIN | 마스터데이터 메뉴 |
| `/master-data/categories` | 카테고리 트리 | HQ_ADMIN | 마스터데이터 메뉴 |
| `/master-data/rate-cards` | 차량 단가표 + 전역 설정 | HQ_ADMIN | 마스터데이터 메뉴 |
| `/master-data/import` | 엑셀 일괄 이관(거래처/품목) | HQ_ADMIN | 마스터데이터 메뉴 |
| `/warehouse` (`''`) | 창고 메뉴 | HQ_ADMIN, WAREHOUSE_STAFF | 설정 → "입출고 실적" 카드 |
| `/warehouse/entry` | 실적 직접 입력 | HQ_ADMIN, WAREHOUSE_STAFF | 창고 메뉴 |
| `/warehouse/list` | 실적 목록 | HQ_ADMIN, WAREHOUSE_STAFF | 창고 메뉴 |
| `/warehouse/import` | 실적 엑셀 일괄 등록 | HQ_ADMIN, WAREHOUSE_STAFF | 창고 메뉴 |
| `/settlement-fees` (`''`) | 정산 대시보드 | HQ_ADMIN | 설정 → "정산 관리" 카드 |
| `/settlement-fees/close` | 월 마감(미리보기/마감 실행) | HQ_ADMIN | 정산 대시보드 |
| `/settlement-fees/breakdown/:transactionId` | 계산 근거 상세 | HQ_ADMIN | 정산서/대시보드에서 건 클릭 |
| `/settlement-fees/statement` | 거래처 정산서 조회/다운로드 | HQ_ADMIN | 정산 대시보드 |
| `/portal` (`''`) | 거래처 포털 홈 | PARTNER_COORDINATOR | 설정 → "거래처 포털" 카드 |
| `/portal/my-transactions` | 내 물량(실적 조회 + 출고명세서) | PARTNER_COORDINATOR | 포털 홈 |
| `/portal/my-statement` | 내 정산서 조회/다운로드 | PARTNER_COORDINATOR | 포털 홈 |
| `/portal/breakdown/:transactionId` | 계산 근거 상세(포털용) | PARTNER_COORDINATOR | 내 정산서에서 건 클릭 |

참고: `/portal/breakdown/:id`는 `/settlement-fees/breakdown/:id`와 **동일한 컴포넌트**
(`BreakdownPage`)를 재사용한다. `apps/web/src/app/features/partner-portal/partner-portal.routes.ts`의
주석에 따르면, 이렇게 분리한 이유는 HQ_ADMIN 전용인 `/settlement-fees` 라우트 가드를
넓히지 않고도 거래처가 자기 계산 근거를 볼 수 있게 하기 위함이며, 데이터 스코프는 API
쪽 `scopeFor()`(`apps/api/src/settlement-fees/settlement-fees.controller.ts:36-44`)가
최종적으로 강제한다.
